# 策略复盘与反过拟合原则

tags: #strategy #review #risk-control #anti-overfit

这份笔记用于约束后续所有 BTC 预测市场策略修复：不能因为某一天某个固定 strike 亏损，就给这个价格写特殊规则。策略必须围绕可迁移的市场状态、相对距离、行情 regime、赔率、流动性和执行成本来调整。

## 核心原则

- 禁止硬编码具体价格点，例如 `$74k`、`$76k`、`$78k`。
- 每次修复必须先描述它解决的通用问题，而不是描述它修掉了哪个具体市场。
- 如果一个规则只在某一个日期、某一个 strike、某一个行情故事里成立，它不能直接进入主策略。
- 允许用具体亏损市场做案例，但最终落地条件必须转写为通用变量，例如 `strike_distance_pct`、`time_to_expiry`、`btc_regime`、`spot_to_strike_velocity`、`side`、`market_type`、`entry_price`、`spread`、`liquidity`、`recent_loss_cluster`。
- 策略修复必须优先降低错误入场概率，而不是依赖止损反复救场。

## 当前策略更适合的行情

### 更适合

- `above_below_expiry` 在非极端趋势下、strike 与 spot 的相对关系清晰、赔率没有过度挤压时，策略更容易工作。
- `range_bucket` 在区间边界清晰、BTC 没有贴边剧烈波动时，策略更容易工作。
- 震荡或缓慢趋势环境里，`BUY_NO above` 或 `BUY_YES above` 如果和 BTC 相对位置、资金流、盘口成本一致，可能产生可解释机会。
- 已有持仓部分止盈和移动止盈更适合短周期概率资产，因为它能把部分账面利润变成已实现收益。

### 不适合

- 快速单边突破或假突破密集环境。此时 `BUY_NO` 可能在突破中止损，`BUY_YES` 又可能在回落中止损，出现两边挨打。
- 临近 strike 的高波动区。如果没有更强的方向确认，`BUY_YES` 与 `BUY_NO` 都可能只是买在噪音里。
- `touch_above` / `touch_below` 的 `BUY_YES`，尤其是 `reach/hit/dip/drop` 这类路径目标市场。当前前瞻模拟显示它容易被时间价值、赔率跳变和 BTC 短线反向波动吞掉。
- 高价入场且剩余收益很薄的确定性市场。方向对也不等于正期望，费用、价差和尾部风险会吃掉收益。

## 历史修改复盘

### 原则上合理的修改

- 引入 `BUY_NO`：这是方向空间的补全，不是某个 strike 特化。合理，但必须继续受 regime、赔率和成本约束。
- 加入 BTC regime 与 strike 相对距离：这是从固定价格升级到相对状态，方向正确。
- 禁止实时模拟使用旧缓存：这是数据真实性修复，必须保留。
- 使用实时订单簿 ask/bid 模拟成交和退出：这是执行真实性修复，必须保留。
- 加入持仓状态、同市场冷却、已关闭仓位历史：这是账户真实性修复，必须保留。
- 拆分 `replay_pnl` 与 `paper_account_pnl`：这是统计口径修复，必须保留。
- watchdog 与健康状态：这是系统可靠性修复，和策略过拟合无关，必须保留。

### 需要持续审计的修改

- 针对 `touch_above` / `touch_below` / `expiry_target` 的距离、趋势和赔率过滤：方向合理，因为它解决的是 target 市场结构问题；但参数如距离阈值、价格上限、冷却时长必须继续用跨日期样本验证，不能只由某一次亏损决定。
- `above_below_expiry` 的安全带与接近 strike 过滤：方向合理，因为它处理的是突破区噪音；但不能写成“某个价格附近暂停”，只能写成相对距离、速度、波动率和时间窗口。
- 分批止盈和止盈后再入场：方向合理，但存在过度交易风险。必须持续检查它是否提高已实现 PnL，而不是增加手续费和反复追单。
- 执行压力层是否硬拦截：必须区分研究路径和实盘路径。研究需要保留成交意图样本，实盘必须更保守。

### 可能有刻舟求剑风险的倾向

- 看到某个 strike 当天亏损后，直接说“这个 strike 附近要特殊处理”。
- 看到某个市场 `BUY_NO` 赚钱，就扩大到所有类似名字的市场。
- 看到止损连续触发，就只放宽止损，而不先证明入场质量足够。
- 看到交易次数少，就降低过滤门槛来制造样本。
- 看到某轮回放 PnL 好，就立即把参数推到实时模拟，而不做前后窗口对照。

## 以后每次策略修复前必须回答

1. 这次问题属于哪个通用类别：趋势识别错误、震荡噪音、赔率过薄、流动性不足、执行延迟、重复入场、统计口径，还是数据质量？
2. 这个规则是否依赖具体 strike？如果去掉价格数字，只保留相对变量，它是否仍然成立？
3. 这个规则在 `BUY_YES` 和 `BUY_NO` 上是否对称，还是只修了其中一边？
4. 这个规则在单边上涨、单边下跌、区间震荡、假突破里分别会产生什么副作用？
5. 这个规则会减少坏入场，还是只是减少交易次数？
6. 这个规则是否需要先以观察模式输出拒绝原因，再进入硬拦截？
7. 修复后看 `paper_account_pnl`、最大回撤、交易数、胜率、平均盈亏、连续亏损，而不是只看单轮 `replay_pnl`。

## 推荐的下一步方向

- 暂停或观察模式降权 `touch_above` / `touch_below` / `expiry_target` 的 `BUY_YES`，理由不是某个 target 亏损，而是该类别在前瞻样本中持续表现为负、且亏损机制具有共性。
- 为 `above_below_expiry` 增加通用的突破区噪音识别：使用 `strike_distance_pct`、BTC 15m/1h 速度、波动率、距离到期时间和 recent loss cluster，而不是固定某个 strike。
- 建立 regime 分层报告：按 `uptrend`、`downtrend`、`range_bound`、`volatile` 分别统计 `BUY_YES` / `BUY_NO` 的前瞻结果。
- 建立修改前后对照表：每次改策略后至少保留旧规则 replay 和新规则 replay，对比交易数、PnL、最大回撤、亏损集中度。

## 观察市场不是放弃

`range_bucket`、`touch_below`、`expiry_target`、`company_treasury` 等进入观察模式，只表示它们当前不能直接污染主模拟账户，不表示永久排除。观察模式的目标是持续收集证据，找到适合该结构的专门策略，再经过影子验证后重新进入主链路。

晋级路径：

- `observe_optimize`: 每轮继续记录信号、edge、拒绝原因和 replay 表现，但不进入主账户。
- `promotion_candidate`: 最近样本足够，正 edge 次数足够，replay 有交易、PnL 为正、最大回撤可控，允许进入下一步影子模拟。
- `main_active`: 影子模拟通过后，才允许加入主模拟盘。
- `blocked_research`: replay 已显示负 PnL 或回撤过高，必须先解释亏损机制，再重写专门策略。

新增 `observation-report` 作为晋级仪表盘。它不会放宽交易，只负责让被观察市场持续被量化追踪，防止“观察化”变成“遗忘”。

新增 `side-diagnostics` 作为 YES/NO 侧向复盘。它从主 replay 的 `backtest_*.csv` 读取真实触发过的入场和退出，按 `market_type + side` 汇总 PnL、胜率、费用、平均入场 edge、最差单笔亏损和主要亏损原因。以后讨论“BUY_NO 是否导致恶化”或“BUY_YES 是否应该恢复”时，必须先看这个报告，不能只凭单轮总 PnL 判断。

如果主模拟盘连续多轮没有任何 TAKER，系统允许触发小仓位 `paper_probe`。它不是放松主策略，而是为了防止“零成交导致无法学习”：只允许极小仓位、有限持仓数、实时 ask/价差确认、BTC 相对 strike 与 regime 过滤都通过后，才在已研究的 `above_below_expiry` 上做 YES/NO 探索成交。

`range_bucket` 也可以进入探索仓，但必须满足更严格条件：BTC 现货在区间内部，且距离上下边界都有足够安全边际；YES 价格不能太贵；净 edge 必须明显为正。这样做的目的不是把区间桶直接升级为主策略，而是收集“区间内部、非贴边”的前瞻样本，验证双边界模型是否值得继续推进。

探索仓的 PnL 必须单独复盘，不能直接当作主策略稳定盈利证据。

如果连续零成交导致无法验证过滤器本身，允许触发更小范围的“过滤器挑战仓”：只针对高 edge 但被 BTC regime 拦截的 `above_below_expiry/NO`，用极小仓位验证过滤器是否过度保守。挑战仓亏损说明过滤器正确；挑战仓持续盈利才说明该过滤器需要重新校准。挑战仓不能直接升级为主策略。

2026-06-01 调整：最近 48 轮约 2600 个 SKIP、只有 4 个 TAKER，样本不足已经影响策略验证。处理方式不是放松主风控，而是把 `paper_probe` 调整为“小仓、多样本、有限并发”：

- 连续零 TAKER 触发阈值从 12 轮降到 1 轮。
- probe 单笔从 5 USDC 降到 3 USDC。
- probe 最大持仓从 1 笔提高到 3 笔，每轮最多新增 2 笔。
- 允许 `range_bucket`、`above_below_expiry` 和价格不过高且通过 BTC 过滤的 `touch_below/YES` 做探索仓。
- `range_bucket/YES` 如果 BTC 在区间内部、距离上下边界有安全边际，且净 edge 很高，可允许最高 0.985 的 3 USDC 高确定性探索仓；这只用于补样本，不代表区间桶主策略已晋级。
- 允许一类更窄的高确定性 `above_below_expiry/NO` 探索仓：YES 很低、NO 不超过 0.985、BTC 低于 above strike 至少约 0.5%，并且净 edge 很高时，才用小仓验证。
- 同时提前模拟盘浮盈保护：10% 浮盈先部分止盈，10% 后回吐 4% 触发移动止盈，避免“曾经浮盈但最终亏损”反复发生。

这次调整的目标是提高前瞻样本密度，而不是证明策略已经可实盘。评估时必须单独看 probe 的胜率、平均盈亏、止损率和是否改善 `paper_account_pnl`。

## above_below_expiry 双向策略复盘

`above_below_expiry` 不能简单理解为“BUY_NO 加进来就会赚钱”或“BUY_YES 一亏就永久屏蔽”。它的问题是到期 above/below 结构在接近 strike、临近到期、行情加速突破时，YES/NO 两侧都可能被噪音扫损。

优化方向不是固定禁止某一侧，而是把侧向选择绑定到通用状态：

- `BUY_NO above`: 更适合 spot 明确低于 strike、没有快速接近 strike、YES 动量转弱、NO 价格没有过度拥挤、盘口可成交的环境。
- `BUY_YES above`: 只有在 spot 与 strike 相对位置、速度、剩余时间和盘口共同确认突破延续时才允许，不能只看 YES 短期均线变强。
- 双向都必须经过相同的执行成本、流动性、价差、冷却、recent loss cluster 检查。

因此后续不是“屏蔽 above_below_expiry 的某一侧不管”，而是用 `observation-report` 和影子模拟验证：哪些 regime、距离、速度、赔率组合下，一侧有稳定正期望，再逐步晋级。

截至当前本地 replay，`above_below_expiry/NO` 在主策略下仍是正 PnL，但亏损退出主要来自止损。这说明 `BUY_NO` 本身不是应该被永久屏蔽的问题；真正需要优化的是入场前过滤：BTC 是否正在接近 strike、NO 价格是否过度拥挤、剩余时间是否过短、盘口成本是否吃掉微弱 edge，以及同类方向是否刚发生连续止损。

相反，如果直接恢复 `above_below_expiry/YES`，交易数会增加，但可能引入追突破失败、费用累积和高波动扫损。因此 `BUY_YES` 不能简单打开，必须先通过 side/regime 诊断证明它在特定结构下有正期望。

## 2026-06-03 VPS 前瞻调整

昨晚亏损集中在 `above_below_expiry/BUY_NO` 的临界 strike 场景，尤其是 BTC 仍低于 above strike 但没有明显远离时，短线反抽会让 NO 被快速止损。修复不能写成“某个 66k/68k 附近不做”，而要写成相对状态：

- 对 `above_below_expiry/BUY_NO`，如果 BTC 距离 above strike 在安全带内但 15m/1h 没有明显远离，主仓不再入场。
- `near_strike_above_below_no` 探索仓也必须看到 BTC 正在从 strike 退开，不能再挑战贴近突破位的噪音。
- 为了避免“过滤更严导致长期零成交”，新增独立小仓家族 `touch_below_certainty_no`。它只验证 below/dip 目标还有安全距离、NO 价格高但仍有实时净 edge、BTC 没有明显下跌加速的场景。
- 该调整的目标是同时减少需要止损救场的坏入场，并恢复一部分可解释样本；它不是把 `touch_below` 主策略放开，也不是针对 `$65k` 做特例。

VPS 验证：部署后一轮实时模拟盘在 `Will Bitcoin dip to $65,000 on June 2?` 触发 1 笔 `touch_below_certainty_no` 小仓 BUY_NO，实时 ask 确认后净 edge 约 `0.0235`，执行压力模拟 `robust=1`。这只证明新家族已能产生前瞻样本，不能证明已经稳定盈利。
