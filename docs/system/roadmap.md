# 项目路线图

## 阶段 1：只读研究工具

状态：已开始

目标：

- 抓 BTC 相关预测市场。
- 生成可解释信号。
- 跑基础回测。
- 初步理解风控参数。

已完成：

- 市场发现。
- 市场分类。
- 历史价格拉取。
- 简单动量信号。
- 基础风控。
- CSV 回测输出。
- Taker fee、滑点和安全边际后的净 edge 过滤。

下一步：

- 加入市场分类，区分纯 BTC 价格市场、日内价格范围市场、公司持仓事件市场和间接 BTC 事件市场。
- 加入本地缓存，减少公共 API 抖动影响。
- 改进回测报告，输出胜率、平均盈亏、最大回撤、交易次数。
- 读取市场真实 fee 设置，替换当前默认估算值。

当前建议顺序：

1. 回测汇总统计。
2. 本地缓存。
3. paper order 状态机。
4. 读取市场真实 fee 设置。

## 阶段 2：持续模拟盘

状态：未开始

目标：

- 每隔固定时间扫描市场。
- 生成 paper orders。
- 保存模拟持仓和交易日志。
- 每天生成复盘摘要。

需要实现：

- 本地状态存储，优先 SQLite。
- `paper-run` 命令。
- 每次扫描的行情快照。
- 交易日志和持仓日志。
- 异常告警。

## 阶段 3：策略增强

状态：未开始

目标：

- 不只看 Polymarket 自身价格，还引入 BTC 外部价格源。
- 计算更合理的公允概率。
- 识别市场间相关性和重复风险。

可能方向：

- 接 Coinbase / Binance / OKX 的 BTC 价格。
- 加入波动率和距离到期时间。
- 针对 `above/below` 市场做概率模型。
- 排除过期、接近结算、或描述不清晰的市场。

## 阶段 4：小资金实盘准备

状态：未开始

目标：

- 保持默认不开实盘。
- 明确交易权限、资金权限和停机机制。
- 只允许非常小的仓位测试真实执行。

实盘前必须完成：

- 私钥和 API key 安全管理。
- 实盘交易开关，默认关闭。
- 每日亏损强制停机。
- 异常订单检测。
- 手动 kill switch。
- 完整交易日志。

## 阶段 5：实盘优化

状态：未开始

目标：

- 基于真实小资金执行数据优化滑点、成交和风控。
- 只放大已经被验证的策略。

原则：

- 不因为一次盈利就加仓。
- 不因为一次亏损就重写策略。
- 每次扩大资金前先看最大回撤和最差连续亏损。
